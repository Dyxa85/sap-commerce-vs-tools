## SAP Commerce VS-Tools 0.1.2 – Java imports now resolve

This release fixes the biggest pain point of 0.1.0 and 0.1.1: **Java files full of unresolved imports** for platform and
module classes.

### Install or update

1. Download `sap-commerce-vs-tools-0.1.2.vsix` below (`SHA256SUMS.txt` lets you verify it).
2. VS Code → Extensions → `⋯` → **Install from VSIX…**. Connections and passwords are kept.
3. Open your project. If the _Red Hat Java_ extension is installed, you are **asked once** whether to set up Java – answer
   **Configure Java** (or run _SAP Commerce: Configure Java for this Project…_ yourself).
4. Wait about **3 minutes** for the Java extension to build the project in the background. The red underlines then
   disappear all at once. No reload or restart is needed.

Details: [Java, build and debugging](https://github.com/Dyxa85/sap-commerce-vs-tools/blob/main/docs/java-setup.md).

### What was wrong

I had never run the Java setup against a real Java language server before; this time I did, with the real Red Hat Java
extension on a real 2211 project (234 extensions). It showed four problems:

- **The setup could not write its settings.** The Java extension declares `java.project.*` for the whole window; we wrote
  them per folder, which VS Code rejects. _Configure Java_ therefore did nothing.
- **86 of 234 extensions were invisible.** Platform `core`, `processing` and most modules ship no sources, only
  `bin/*.jar`. Those jars were not referenced, so classes like `SystemSetupParameter` or `PerformResult` stayed
  unresolved.
- **Source folders were missing:** `backoffice/src`, `backoffice/testsrc` and addon sources (more than 500 files in a
  typical project).
- **"Reload project" called a command that does not exist.** The Java server applies the settings by itself.

### Result

| Situation                                             | Imports resolved           |
| ----------------------------------------------------- | -------------------------- |
| Java server running, no Java settings                 | 0 of 8 in the test file    |
| After _Configure Java_ (server already running)       | 8 of 8 after ≈ 2.5 minutes |
| 21 random files: code, tests, web, backoffice, addons | **239 of 239**             |

### Also in this release

- A one-time offer to run the Java setup (remembered per workspace with _Don't ask again_).
- `sapcommerce.java.*` settings are window settings (a warning in the log is gone).
- A redesigned README with logo and screenshots, and an [ADR](https://github.com/Dyxa85/sap-commerce-vs-tools/blob/main/docs/adr/0001-java-project-model.md) that is now _Accepted_ with these measurements.

### Known limits

- Extensions that are **not** in `localextensions.xml` are not part of the project, so their classes stay unresolved by design.
- Verified on one real 2211-jdk21 platform and macOS. Not measured: memory use of the Java server.
- **Not yet verified:** the MCP server from Copilot's agent mode, a real `ant build` started from the task.
- Not implemented: ACL and Polyglot Query editors, debugger value renderers, CCv2 Cloud Portal features. See the
  [roadmap](https://github.com/Dyxa85/sap-commerce-vs-tools/blob/main/ROADMAP.md).
