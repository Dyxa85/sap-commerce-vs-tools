## SAP Commerce VS-Tools 0.1.1 – easier to find, easier to set up

Developer tools for **SAP Commerce** (`2211-jdk21`) in **VS Code 1.101+**. Unofficial: not affiliated with SAP SE.
This release is about **finding things and getting started**; it also adds the CCv2 view and a real folder view of every extension.

### Install or update

1. Download `sap-commerce-vs-tools-0.1.1.vsix` below (`SHA256SUMS.txt` lets you verify it).
2. VS Code → Extensions → `⋯` → **Install from VSIX…** (or `code --install-extension sap-commerce-vs-tools-0.1.1.vsix`).
   Installing over 0.1.0 keeps your connections and passwords.
3. Click the new **SAP Commerce** icon (a hexagon with `< >`) in the activity bar.

### What's new

- **Side bar "SAP Commerce"** with **Connections**, **Features** (a clickable table of contents of everything the extension
  does, with the shortcut, menu or file type where each feature also lives), **Commerce Project** and **CCv2**. The two
  project views moved here from the Explorer; each explains itself when it has nothing to show.
- **One page for connections**: add, edit, test and remove, with an explanation of what the hAC connection is for
  (it is only needed to run queries, scripts and imports on a running instance). Open it with the **+** / gear in the
  Connections view or _SAP Commerce: Open Connection Settings_. The step-by-step input boxes remain as an alternative.
- **Get started**: a walkthrough under _Welcome → Walkthroughs_, a one-time hint after the first start, _New ImpEx File_
  and _New FlexibleSearch File_, and context-menu entries to run SQL (`.sql`) and Groovy (`.groovy`).
- **Real folder structure per extension** in the Commerce Project view (`gensrc`, `resources`, `src`, `testsrc`,
  `build.xml`, `extensioninfo.xml` …, including the Java sources, packages merged like in an IDE). The type system, beans,
  Spring, process and ImpEx groups are in a _Commerce overview_ node below. Build output is hidden
  (`sapcommerce.project.hiddenEntries`); new files appear without a refresh.
- **CCv2 view**: the repository as it is on disk (`core-customize`, `js-storefront`, …) and an outline of
  `manifest.json` (versions, extension packs, extensions, properties, config per persona, aspects with webapps); a click
  jumps to the entry. It reads files only – no Cloud Portal access is needed.

### Fixed

- A login that was still running while the password or settings changed could resurrect an old authenticated client, so
  the next request skipped the password prompt.
- A settings warning in the log (`sapcommerce.project.hiddenEntries`).

### Known limits

- Developed and tested on **macOS**. CI runs unit tests and tests inside VS Code on Ubuntu, macOS and Windows; one
  Windows test of the stored-password flow has failed intermittently in CI (twice in the last ten runs) and was made
  stricter in this release, so please report it if you see odd password prompts on Windows.
- **Not yet verified:** the Java setup against a running Red Hat Java language server, the MCP server from Copilot's
  agent mode, a real `ant build` started from the task, how the new side bar looks in every VS Code theme.
- **Not implemented:** ACL and Polyglot Query editors (no public specification), debugger value renderers (no VS Code
  API), CCv2 Cloud Portal features such as builds and deployments (needs an API token to verify). See the
  [roadmap](https://github.com/Dyxa85/sap-commerce-vs-tools/blob/main/ROADMAP.md) and
  [per-feature evidence](https://github.com/Dyxa85/sap-commerce-vs-tools/blob/main/docs/parity.md).
