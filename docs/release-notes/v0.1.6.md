## SAP Commerce VS-Tools 0.1.6 – all projects in one tree, Git changes, less Java memory

### Commerce Project and the side bar

- **All projects of the opened folder.** Open one folder above them: the extension finds the SAP Commerce backend and every
  JavaScript project (a folder with a `package.json`, e.g. an Angular storefront) and shows each under its folder name with
  its own icon.
- **Backend tree.** _Configuration_ is the folder `hybris/config` as it is on disk. A new _Root_ entry mirrors the repository
  folder without `core-customize`.
- **Git changes instead of problem colours.** Extensions were all yellow or red. Now only changed files and the folders and
  extensions that contain them are coloured, with the Git extension's colours and badges.
- **The file you edit is selected in the tree**, like in the Explorer (`sapcommerce.project.autoReveal`).
- **New view _Changes_**: every file Git reports as changed, per repository, under the name of the project. A click shows the diff.
- **CCv2** moved out of Commerce Project and shows the outline of `manifest.json`. Order of the views: Connections, Features,
  CCv2, Changes, Commerce Project.

### Java: memory, JDK, tests

- **Less memory.** A running server on a 234-extension project held about 350 MB of live objects but grew towards the
  allowed 4 GB, because the default collector never gives heap back. _Configure Java_ now writes G1 with a 1.5 GB limit that
  returns unused heap.
- **The JDK the platform requires** (21 for 2211-jdk21) is set as the project's runtime, so analysis and **test runs** no
  longer use the newer JDK bundled with the Java extension (25 in 1.58).
- No Gradle/Maven import by the Java server, and no Mockito/Byte Buddy warnings in test runs.
- Opt out with `sapcommerce.java.manageServer`.

### Update

1. Download `sap-commerce-vs-tools-0.1.6.vsix` below (`SHA256SUMS.txt` lets you verify it), VS Code → Extensions → `⋯` →
   **Install from VSIX…**, reload the window.
2. Run _SAP Commerce: Configure Java for this Project…_ **again**. It replaces your `-Xmx4G` and sets the JDK.

### Good to know

- Colours and the selection of the open file depend on the Git extension and on VS Code's tree; they are covered by tests
  on the data, not yet by screenshots.
