## SAP Commerce VS-Tools 0.1.7 – backoffice imports resolve, unit tests find the platform

Two fixes for the Java setup, both found on a real 2211-jdk21 project.

### Fixed

- **Imports of backoffice classes were unresolved**, for example
  `de.hybris.platform.platformbackoffice.variant.VariantAttributesSectionRenderer`. The backoffice module of an extension is
  compiled into `resources/backoffice/<extension>_bof.jar`, a place the generated settings did not list. The classes of web
  modules (`web/webroot/WEB-INF/classes`) and of `backoffice/classes` were missing in compiled mode as well. All three are
  part of the project now. Checked with a real backoffice file: 5 of 5 imports resolve.
- **Unit tests failed with "Can not determine platformhome"** (`Can not determine path to core-items.xml`). The platform
  finds its home through `core-items.xml` in `ext/core/resources`, and a test run had no `resources` folder on its class
  path. _Configure Java_ now writes the `resources` folders of the extensions to `java.test.config`. The exact error was
  reproduced with the platform's own classes outside VS Code, and the resources fix it.
- _Configure Java_ no longer fails when a setting of another extension does not exist (`java.test.config` belongs to the Test
  Runner for Java); it is skipped and logged.

### Update

1. Download `sap-commerce-vs-tools-0.1.7.vsix` below (`SHA256SUMS.txt` lets you verify it), VS Code → Extensions → `⋯` →
   **Install from VSIX…**, reload the window.
2. Run _SAP Commerce: Configure Java for this Project…_ **again** (it rewrites the Java settings and packs the new jars).

### Good to know

- Not verified: a unit test run through the Test Runner for Java itself. Tests that need more than the resources (for example
  Spring contexts of other extensions) may report the next missing piece.
