## SAP Commerce VS-Tools 0.1.3 – the Java setup can no longer be missed

0.1.2 fixed the Java setup itself (239 of 239 imports resolved on a real platform), but it only asked once, in a
notification that is easy to overlook. If you did not click it, nothing changed and every Java file still showed
unresolved imports. This release makes the setup impossible to miss.

### What you will see now

While a SAP Commerce project is open, the _Red Hat Java_ extension is installed and Java is not set up yet:

- a **warning in the status bar**: _Java: set up SAP Commerce_ (click it),
- a **clickable entry at the top of the Commerce Project view**: _Java is not set up – click to configure_,
- a **quick fix on the red underlines** of Java files (lightbulb → _Set up Java for this SAP Commerce project…_).

Click any of them, confirm, and wait about **3 minutes** while the Java extension builds the project in the background.
The red underlines then disappear all at once, and the hints go away by themselves. The status bar tells you that the build
is running.

If you chose _Don't ask again_ in the notification, the hints stay off for that workspace; the command _SAP Commerce:
Configure Java for this Project…_ is always available.

### Install or update

1. Download `sap-commerce-vs-tools-0.1.3.vsix` below (`SHA256SUMS.txt` lets you verify it).
2. VS Code → Extensions → `⋯` → **Install from VSIX…** and reload the window. Connections and passwords are kept.

### Good to know

- **Open the folder you work in, however high up.** The setup also works when you open a parent folder that contains
  several repositories (checked with your layout: a folder holding the CCv2 repository and a second repository).
- Extensions that are **not** in `localextensions.xml` are not part of the project, so their classes stay unresolved by design.
- The output channel **SAP Commerce** now says why the hint is shown or not, which helps if it does not appear.
- Details and measurements: [Java, build and debugging](https://github.com/Dyxa85/sap-commerce-vs-tools/blob/main/docs/java-setup.md).

### Known limits

- Verified on one real 2211-jdk21 platform and macOS. Not measured: memory use of the Java server.
- **Not yet verified:** the MCP server from Copilot's agent mode, a real `ant build` started from the task.
- Not implemented: ACL and Polyglot Query editors, debugger value renderers, CCv2 Cloud Portal features.
  See the [roadmap](https://github.com/Dyxa85/sap-commerce-vs-tools/blob/main/ROADMAP.md).
