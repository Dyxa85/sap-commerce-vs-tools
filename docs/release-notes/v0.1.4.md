## SAP Commerce VS-Tools 0.1.4 – Java uses the result of your Ant build

0.1.3 made the Java setup visible. This release makes it light enough to run: with all 234 extensions compiled from
sources, the Java server ran out of its default 2 GB of memory ("The Java Language Server encountered an OutOfMemory
error") and spent minutes under load.

### What changed

- **Platform and modules come from your `ant build`**, so the editor sees exactly the classes Ant compiled – no second,
  possibly different compilation, no surprises at the next build.
- **Your own extensions stay sources.** That is what gives you errors while you type, completion and rename. Ant compiles
  them as well, but a compiled class cannot do those things.
- The Java server only reads **jars**, not `classes` folders (measured: such an entry is ignored). _Configure Java_
  therefore packs the `classes` folders that Ant produced into `.sapcommerce/libs/*.jar` – 143 jars in 7 seconds, one second
  when nothing changed – and refreshes them after every successful Ant target.
- Not built yet (`ant clean`)? Those extensions fall back to their sources, and the generated models to `bootstrap/gensrc`.
- New setting `sapcommerce.java.mode`: `compiled` (default) or `sources` (the old behaviour).

### Measured (234 extensions, default 2 GB heap, real Red Hat Java 1.56)

|                          | `sources`                     | `compiled`      |
| ------------------------ | ----------------------------- | --------------- |
| Imports of the test file | 8 of 8                        | **8 of 8**      |
| First build              | 4.5 min, then minutes of load | **about 2 min** |
| Restart                  | minutes busy                  | **15 s busy**   |
| Peak memory              | 2.4 GB and more               | **1.5 GB**      |

All imports of 6 sample files in your own extensions resolved (81 of 81).

### Update

1. Download `sap-commerce-vs-tools-0.1.4.vsix` below, VS Code → Extensions → `⋯` → **Install from VSIX…**, reload.
2. Run `ant build`, then _SAP Commerce: Configure Java for this Project…_ again (it replaces the old settings it wrote) and
   add `.sapcommerce/` to your `.gitignore`.

### Good to know

- The sources of platform modules are not part of the project in `compiled` mode: opening one shows unresolved types, and
  Go to Definition into a platform class opens the class, not its source. Choose `sapcommerce.java.mode: sources` (and give
  the Java server `-Xmx4G`) if you need that.
