# Security review (pre-1.0)

Scope: everything in this repository as of the 1.0 candidate. Method: reading the code paths that handle credentials,
network, files, processes and webviews, plus targeted tests. This is a self-review, not an external audit.

## Assets and trust boundaries

| Asset                                   | Where it lives                                             |
| --------------------------------------- | ---------------------------------------------------------- |
| hAC passwords                           | VS Code SecretStorage, key = connection URL + user name    |
| Query results, scripts, ImpEx           | memory, results panel, optional files the user exports     |
| Workspace files (`*.xml`, `*.impex`, …) | untrusted input (a cloned repository can contain anything) |
| Instance responses                      | untrusted input (HTML/JSON from a server)                  |

## Findings and how they are handled

| #   | Threat                                                                                                          | Mitigation                                                                                                                                                                                                               | Evidence                                                                |
| --- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| 1   | A cloned repo's workspace settings add a connection to an attacker's host and the stored password is sent there | Connections from workspace settings are ignored in untrusted workspaces; passwords are keyed by URL **and** user, so a changed URL never reuses a stored password                                                        | `package.json` capabilities; `ConnectionManager.secretKey`; model tests |
| 2   | Password sent in clear text                                                                                     | TLS verification on by default, disabling it is per connection. `http://` to a non-loopback host needs an explicit confirmation per session (**added during this review**). MCP queries are refused for such connections | `isInsecureRemote` tests                                                |
| 3   | Redirect to another host leaks credentials/cookies                                                              | The HTTP session never follows redirects; every request is resolved against the configured base URL                                                                                                                      | `core/src/hac/http.ts`                                                  |
| 4   | Secrets in logs                                                                                                 | Output channel redacts known secrets (`Logger.addSecret`), passwords never appear in command lines                                                                                                                       | `util/redact` tests                                                     |
| 5   | XSS through instance data or project files in a webview                                                         | Strict CSP (`default-src 'none'`, nonce for style and script, no remote resources), all text escaped, SVG built from escaped strings; messages from the webview are type-checked                                         | `results-html`, `type-html`, `graph-process` tests                      |
| 6   | Opening arbitrary files from a webview message                                                                  | Only `file:` URIs that the extension or server produced are opened; node ids from diagrams are used as lookup keys, never as paths                                                                                       | `openTarget`, `openLocation`                                            |
| 7   | Shell injection through Ant targets/arguments (tasks, `tasks.json`, input box)                                  | Targets must match `[A-Za-z][\w.-]*`, arguments a fixed pattern (`-Dkey=value`, a few flags); the process is started as `/bin/sh -c` with that validated text, or `cmd /c`                                               | `build-java.test.ts` (injection attempts rejected)                      |
| 8   | Commands that start processes in an untrusted workspace                                                         | Build/server/Java commands refuse to run until the workspace is trusted (VS Code's task API additionally requires trust)                                                                                                 | `requireTrust`                                                          |
| 9   | CSV/spreadsheet formula injection in exports                                                                    | Cells starting with `=`, `+`, `@` or a non-numeric `-` are prefixed                                                                                                                                                      | `util.test.ts`                                                          |
| 10  | Writes to an instance by accident                                                                               | Groovy runs in rollback mode by default; commit, import and log-level changes ask first; protected connections always ask                                                                                                | host tests (`hac.test.ts`)                                              |
| 11  | AI tools changing data through the MCP server                                                                   | Tools are read-only; query tools are off by default, need a user-scope setting and a confirmation per start; only a single `SELECT` passes the guard, never commit mode; results capped                                  | `mcp.test.ts`                                                           |
| 12  | Password handed to the MCP child process                                                                        | Passed in the child's environment only (not on a command line), read from SecretStorage at start. Standalone use takes a password **file**                                                                               | `docs/mcp.md`                                                           |
| 13  | Denial of service by huge files                                                                                 | Quadratic algorithms removed (formatter, overlap resolution); 3.9 MB ImpEx parses in ≈125 ms; graphs capped (80 type nodes, 400 module nodes); output of MCP tools capped                                                | corpus runs, layout test with 300 nodes                                 |
| 14  | Supply chain                                                                                                    | 103 production packages, all MIT/ISC/BSD/BlueOak (no copyleft); exact versions pinned in the lockfile; Dependabot enabled; notices shipped in the VSIX                                                                   | `THIRD-PARTY-NOTICES.txt`                                               |
| 15  | Telemetry / data leaving the machine                                                                            | None. The only network traffic is to the hAC URLs the user configured                                                                                                                                                    | code review                                                             |

## Not covered

- No external penetration test or fuzzing campaign. The parsers were exercised with the maintainer's real project files (≈1,400 files), not with adversarial input.
- The MCP read-only guard is a keyword check, not a SQL parser. The hAC account itself should be a least-privilege user; do not point AI tools at a production system.
- The Java settings generator and Ant tasks run user-trusted tools (`ant`, `hybrisserver.sh`) from the platform directory; a malicious repository can ship malicious scripts there. That is why those commands need a trusted workspace.
- Windows-specific quoting of `cmd /c` was not exercised on a Windows machine (only in unit tests of the generated command line).
